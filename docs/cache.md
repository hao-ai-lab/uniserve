# Paged KV ownership

`PrefixCache` owns equally sized allocation units shared by all resident attention layers. Layers with the same history window and KV page shape form a cache group. A group's logical page occupies one or more units; each unit contains columns of key and value planes. Layers read borrowed `mha.State` views through the table assigned by the pool. Models declare dimensions and visibility, while the runtime owns allocations and physical addresses.

`plan_units` derives group pages, columns, tables and storage bytes from the model's cache configuration. `num_units` measures physical allocation capacity; it is distinct from the number of logical pages and tokens of any group. A serving owner reserves unit zero for graph padding. Direct library storage treats every unit as ordinary addressable memory.

The worker resolves an unset `--page-size` to the largest power of two up to 64 whose resulting group pages every resident attention reader supports. Ranks agree on the smallest supported base size. An explicit value remains the operator's choice and unsupported combinations fail during preparation. Groups with smaller token rows hold proportionally more tokens per page; their page sizes need not equal the base size.

The engine allocates units and advances each group's logical page interval independently. Windowed groups can retire pages outside their history bound while full-attention groups retain the sequence. Request tables carry absolute start pages, preserving token positions when old pages retire. Admission charges the units required by every group, and transfer descriptors identify each group's layers, heads and token intervals.

The worker's native `BlockTables` owns installed assignments, per-slot capacity, alternative-prefix slots, and change detection. A `GroupTable` maps absolute token intervals to physical unit spans, including pages that occupy several units. Installing a batch checks every table before issuing device writes; only changed rows, start pages, and lengths are copied to the device. Host assignments commit after those copies are submitted successfully. Python retains the device tensors and bounded pinned host buffer rings, and slot release does not wait for unrelated queued device work.

Attention preparation selects visible page ranges in Rust for the complete batch. Writing rows extend their cached prefix; read-only canvas rows need capacity only for that prefix. Windowed groups select history from the first query's reach through the last query, bounded by installed pages. The cache manager checks physical writes against outstanding transfers before returning borrowed `TablePages`. These views retain their assignments through later slot updates. Prefill, resident decode and graph warmup share this selection: device gathers consume widths and first-page mirrors, while host tensor construction expands physical unit rows only when needed.

The native `KVCacheManager` retains execution accesses, exports and import destinations until their physical accesses retire. All three use the same token-interval overlap rules and completion signals. Model calls sharing a batch fence coalesce their unit ranges; the runner orders these calls, while independent transfers prevent overlapping writes. Reusing units also waits for model accesses. Export reservations use their existing `BufferId`, and revocation preserves every unfinished reader. Failures surface only for the selected request or buffer and continue to block reuse.

Python binds the manager to numerical cache views and transport copies. Transfers preserve each group's interval and installed base, including partial final pages and different pipeline or head partitions. An import's task and workspace remain live until its stream and transport readers finish; its destination remains reserved until adoption or abandonment. A rejected duplicate import leaves the first reservation intact.

Storage owners share a native `Completion` for each asynchronous access. CUDA fences and transport acknowledgments resolve these signals; tensor references alone do not establish completion. A successful signal permits reuse, while failure preserves the original error and keeps the affected storage held. Waiting releases the Python GIL, and observers run outside the completion lock.

Recycling resets the state a subsequent writer reads, including FP8 initialization flags and scales. Payload bytes may remain when every group's representation keeps them finite and visibility excludes unwritten positions. Pools containing different storage element types clear recycled payloads because reinterpreting stale bytes may produce nonfinite values. Explicit `zero_units` clears payloads and metadata regardless of representation.

Serving attention keeps host mirrors of sequence lengths and start pages. Worker execution contexts disable deriving those mirrors from device tensors and reject a missing mirror when a selected provider needs it. Direct Python callers may allow derivation outside capture. These obligations accompany the [attention input contract](attention.md).
