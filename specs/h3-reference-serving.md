# H3 reference checkpoint contract

`resolve_catalog_entry(("minimax-h3-ref",), root=root)` validates the top-level pinned MiniMax-H3 repository and selects `transformer_ref` for the denoiser, with shared `text_encoder`, `vae`, and `audio_vae` components. `resolve_base_h3_contract(root, reference=True)` exposes its recipe and capabilities. The immutable model identity is `hf://MiniMaxAI/MiniMax-H3@9bfb6693f2cf6de171db46d1aa586f67d773a1da`; FastVideo reference code is `a943220c115228ade5d57b3bab9a6a87fd600a10`.

Local roots require revision receipts for every consumed configuration, index and shard. The denoiser requires 14 indexed shards; nested task exports, missing components, unsafe shard paths, other revisions and distilled manifests fail validation. Revision receipts establish provenance, not recomputed weight hashes.

The contract fixes output to 480×832×124 at 24 FPS, with 32 kHz audio. Sampling uses the base CPU-FP32 50-point uniform grid, shifts 12/3, 49 transformer forwards and guidance 1.0. Attention is dense for both reference and target spans; reference-aware VSA is not implemented. The capability is `references: {max: 1, kinds: [image]}`.

By default, checkpoint inspection and worker catalog resolution automatically select the reference recipe when a local pinned root contains a top-level `transformer_ref`. Its configuration and weight sources are validated instead of the base denoiser. Explicit distilled manifests and operator sidecars retain precedence; a root without `transformer_ref` selects the base recipe.

## Execution boundary

HTTP admission reads the resolved contract's exact `references: {max: 1, kinds: [image]}` capability, independently of the served-model alias. `/v1/videos` and `/v1/videos/sync` accept one inline standard-base64 PNG/JPEG with `type=image`, `task=reference`, and `role=reference`. URLs, other kinds/tasks/roles, audio flags, multiple references, invalid encoding, unknown fields, and invalid image geometry return HTTP 400 with the violated rule. Compressed sources are limited to 32 MiB; headers are checked before raster allocation, with axes in 32..=4096 and divisible by 32, and decoder allocation bounded to 256 MiB. Empty lists and omitted references have identical text-only behavior.

Worker-local geometry expands the admitted prompt with the checkpoint processor's label and merged-image spans without modifying serialized admission geometry. Every entry owner resolves the same tags and row counts before product allocation. The encoder publishes conditioning states and presentation tags for one decoded THWC image; text-only operations publish the original single conditioning tensor. Reference dimensions must be multiples of 32 within the decoded-product bound of 4096 per axis. Reference workers reserve this image-row capacity; base workers do not allocate reference pages.

Preparation consumes conditioning, tags, and the declared decoded pixel product, in that order. Inline pixels remain request-owned host tensors that can feed both encoder and denoiser entries. Their source identity is not a scheduled producer dependency; completion ordering excludes host-staging sources while enforcing request ownership. Transported pixels use device-product leases. Entry-result validation uses the outputs selected by each operation, so a reference-capable encoder can return only conditioning for a text-only request. The conditioner refines the entire presentation rather than the original prompt length. The denoiser input-stage replicas own FP32 causal image-posterior weights from the shared video-VAE source, independently of video-decoder entry placement; colocated owners share those weights. Reference VAE rows are fixed conditioning, separate from target solver rows and target RNG. Later pipeline stages resolve the same presentation geometry without requiring local encoder or image-VAE weights.

Target layout, packed latent rows, request storage, decoder scratch, output schemas, warmup inputs, and RGB assembly use the checkpoint contract's spatial geometry. Reference workers reserve 124 frames at 480×832 and reject configured temporal capacities smaller than that recipe; base and distilled workers retain their configured frame capacity at 768×1344. CPU tests cover request descriptors through real Qwen image/text modules with synthetic weights, planned presentation pages, real causal image encoding, and transformer input tensors/rotary coordinates without a colocated decoder. They also cover exact no-reference conditioning and noise bytes, decoder latent windows, and exact RGB overlap/normalization products. `tests/python/e2e/test_h3_reference_cpu.py` additionally exercises the production HTTP router, Rust admission and scheduler, native IPC, worker preparation, encoder, image posterior, layout, and transformer inputs with synthetic weights. It uses a one-forward, 39-frame CPU fixture and stops explicitly at transformer inputs; it does not generate a video or claim full-recipe numerical quality. Its tiled-identity projection/conditioner weights permit byte-exact comparison with the real small Qwen encoder on the source RGB image and the unchanged language-only path. The test verifies one VAE reference segment after the padded presentation and before target audio/video, with image time 75 and target start 76. CPU-owned buffers use synchronous host copies; CUDA owners retain streams and page-locked host captures.

## Single-process deployment

`uniserve serve <root-with-transformer_ref> --model-description minimax-h3` uses checkpoint inspection to select the reference contract. `UNISERVE_H3_VARIANT=base` explicitly selects the base denoiser from the shared root; `UNISERVE_H3_VARIANT=ref` pins reference selection. Distilled manifests cannot be overridden by either variant. One process exposes one loaded model, not aliases for multiple weight sets.

`scripts/h3/serve-h3-ref.sbatch` serves `minimax-h3-ref` on port 8102 using one four-GPU rack-3 tray, dense quality precision and the pinned root supplied positionally. The deployed command is `sbatch --export=NIL serve-h3-ref.sbatch ref <root>`. The endpoint helper validates the reference contract and publishes readiness without controlling server lifetime. `smoke-h3-ref.py <image.png>` sends one text-only and one single-image request serially, saving their MP4s under `/mnt/lustre/vlm-wlsaidhi/fastvideo/eval/uniserve-smoke/ref/`. Deployment scripts are syntax-checked; CPU input evidence does not establish GPU generation readiness or media quality.
